# 吉祥物順暢化踩坑紀錄（2026-10-20～21）

記帳首頁的 3D 吉祥物是一個 iframe（`web/pet/index.html`，Three.js），用 Flutter 的
`HtmlElementView`（platform view）蓋在整個頁面上。牠站在卡片上、會爬梯子、會被抓起來、
跟著畫面捲動。為了讓牠「不閃、不卡、不慢一拍」踩了下面這些坑。

相關檔案：

- `lib/features/tally/pet/tally_pet.dart`：吉祥物邏輯、位置、影子、泡泡、手指判定
- `lib/features/tally/pet/pet_view_web.dart`：iframe 嵌入、跟 iframe 溝通
- `web/pet/index.html`：3D 本體

---

## 1. 落地、抓起、爬梯子時閃一下

**現象**：吉祥物一落地、一被抓起來、一爬完梯子，整隻就閃一下（消失一幀再出現）。

**原因**：Flutter 網頁版的 platform view 在元件樹裡的位置一變，就會把整個 iframe
拆下來再重貼一次。原本寫法是：

```dart
Stack(children: [
  if (plat != null) shadow(),   // 落地才加影子
  if (bubble != null) bubble(), // 有話才加泡泡
  petView(),                    // 3D iframe
])
```

條件一成立，iframe 前面就多一個元件，它在 Stack 裡的位置從第 0 個變第 1 個，於是重貼，
看起來就閃一下。

**修法**：Stack 的子元件數量**永遠固定**，每個都一直放著，只切換看不看得見
（透明度、大小）。

> 規則：同一個 Stack 裡，platform view 前面的子元件數量不能變。

---

## 2. 隱藏時透明度不能設 0

**現象**：吉祥物等 3D 準備好才進場，進場前用 `Opacity(0)` 藏起來，結果 iframe 根本沒在畫，
出來的時候才開始初始化、閃一下。

**原因**：透明度 0 的 platform view，Flutter 直接不畫，iframe 也就不算「在畫面上」。

**修法**：用 `0.01`。肉眼看不到，但它有被畫，iframe 會在背後先準備好。

---

## 3. 蓋滿畫面的 iframe 擋住底下的雪球

**現象**：加了吉祥物之後，結餘卡上的 3D 雪球點不了、也轉不動。

**原因**：吉祥物 iframe 蓋滿整個頁面，手指全被它吃掉。只對 iframe 設
`pointer-events: none` 不夠，因為：

- Flutter 在 iframe 外面還包了一層 `flt-platform-view-slot`；
- 這層在 `flt-glass-pane` 的 **shadow root** 裡面，外面的 CSS 選不到；
- Flutter **每次重畫都會把它的 `pointer-events` 寫回 `auto`**，直接改 style 下一幀就被蓋掉。

**修法**：在那個 shadow root 裡塞一條 `!important` 規則，壓過 Flutter 每幀寫的值：

```css
flt-platform-view-slot:has(> slot[name="flt-pv-slot-<id>"]) {
  pointer-events: none !important;
}
```

（見 `pet_view_web.dart` 的 `_passThrough`）。驗證方式：在雪球 iframe 掛 pointerdown
計數，無頭 Chrome 點一下，計數從 0 變 1。

---

## 4. 進場時 3D 還沒好

**現象**：吉祥物進場動畫跑到一半，3D 才出來，前半段看不到。

**修法**：iframe 畫好前兩幀才 `postMessage({pet:{ready}})`，Flutter 收到才開始進場；
另外留一個 12 秒保險，萬一沒收到也照樣開始。

---

## 5. 講話時字跑不出來

**現象**：App 開很久之後點吉祥物，新的一句話有些字是空白，過一下才出現。

**原因**：CanvasKit 不會一次載完整套中文字型，遇到沒用過的字才去下載那幾個字。
第一次說某句話時，裡面的新字還沒下載好。

**修法**：用 `Offstage` 放一段包含**所有台詞**的 Text（`_allSaid`），一開始就排版一次，
字型就會先下載好。

> 新增台詞（`_say` 的話）時要記得加進 `_allSaid`。

---

## 6. 捲動時慢一拍（這次最難的）

### 6-1. postMessage 是非同步的

**現象**：捲動時吉祥物跟不上卡片，像被拖著走。

**原因**：Flutter 每幀用 `postMessage` 把位置送給 iframe。postMessage 是非同步的，
iframe 下一輪才收到，3D 就比 Flutter 晚一幀畫。

**修法**：iframe 跟 App 是同一個網站，可以直接呼叫 iframe window 上的函式：

```dart
(iframe.contentWindow as JSObject).callMethod('petPose'.toJS, pose.jsify());
```

iframe 那邊的 `window.petPose` 收到位置就**立刻畫一幀**。這樣 3D 跟 Flutter 就在同一幀畫。
iframe 自己的 rAF 迴圈改成「超過 250ms 沒被呼叫才自己畫」，避免一幀畫兩次。

### 6-2. Ticker 讀到的是上一幀的卡片位置

**現象**：改成直接呼叫之後還是慢一點點。

**原因**：Flutter 每一幀的順序是：

1. **Ticker（動畫計時器）**：吉祥物在這裡算位置，問「我站的卡片在哪？」
2. **排版（layout）**：捲動時卡片在**這一步**才搬到新位置
3. **畫（paint）**

第 1 步比第 2 步早，所以吉祥物拿到的永遠是上一幀的卡片位置。一直捲就一直差一幀。

**修法**：做一個自訂 RenderObject `_Follow`（`RenderProxyBox`），在 **paint 的那一刻**
（排版已經完成）再讀一次牠站的那張卡片位置，算出差了多少（`dy`）：

- `paint`：整層平移 `dy` 再畫（影子、泡泡、門、降落傘等都包在裡面）
- `hitTestChildren`：手指判定也平移 `dy`（不然看得到卻按不到）
- `applyPaintTransform`：讓座標換算也正確
- **同一刻**把 `y + dy` 用 `petPose` 送給 3D iframe

`_followDy()` 每幀只算一次（用 `_frameNo` 判斷），影子層和泡泡層兩個 `_Follow` 共用結果，
送 3D 也只送一次。Ticker 裡就不再送位置了。

> 規則：要跟著捲動的東西，不要在 Ticker 裡讀別的元件位置；在 paint 時讀。

### 6-3. 卡片捲出畫面後掉下去再掉回來，不夠順

**原本**：站的卡片捲出去，吉祥物就往下掉，再從上面掉回來。

**修法**：改成用拋物線**跳到最近、看得到的卡片**（`_hopToNearest`，0.55 秒）：

- 距離算法：`|Δy| + |Δx| × 0.5`，太靠近頂端（`y < 120`）的卡片加 220 懲罰，不往上面跳
- 跳的途中目標卡片還在捲，就每幀重新讀目標位置，跟著它跑
- 跳到一半目標也捲出去了，就再找下一張；真的沒卡片才掉下去

## 測試上的坑

- 無頭 Chrome 用軟體繪圖，3D 很慢，**看不出順不順、閃不閃**，那部分要在手機上看。
- 能用數字驗的就用數字：例如在 paint 時記下吉祥物的 y 和卡片的 y，捲動後比對差值是不是 0；
  雪球點不點得到用 pointerdown 計數。
- 等東西出現用 `until` 輪詢，不要寫死 sleep（見 `CLAUDE.md`「測試」）。
- 部署後手機上第一次開常是舊版（service worker 快取），要完全關掉 App 再開。

## 一句話總結

| 坑 | 一句話 |
|---|---|
| 閃一下 | platform view 前面的子元件數量不能變 |
| 藏起來 | 透明度用 0.01 不要 0 |
| 擋手指 | shadow root 裡塞 `!important` |
| 字空白 | 所有台詞先排版一次，預載字型 |
| 慢一拍（通訊） | 不用 postMessage，直接呼叫 iframe 的函式 |
| 慢一拍（時機） | 不在 Ticker 讀位置，在 paint 時讀 |
| 捲出畫面 | 跳到最近的卡片，不要掉下去 |
